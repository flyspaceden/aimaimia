# 平台基金账本发布与回退说明

状态：本地候选，未推送、未部署。基线 origin/main@101ada3d，分支 codex/platform-fund-ledgers-20260908。不得整体合并旧 staging。

## 迁移边界

新增公司基金表、平台基金审计表与触发器、私有凭证表、付款请求幂等表。没有旧 Reward 数据重写、回填或转账；平台审计期初快照写入新表。产业基金新的公司账从零起步。

发布时必须暂停旧版本分润消费者并排空在途任务，再在审批通过的精确 SHA 上执行迁移和启用新版本。记录迁移完成时刻及新版本启用时刻，确认只有一种代码版本执行新计提。不能仅靠订单创建时间决定新旧账；已存在分配的 RewardAllocation 幂等键不变，重放不重复分配。

私有付款凭证保存在 PostgreSQL BYTEA（每份最多 5MB），应随数据库纳入备份与容量监控。只有拥有公司账查看且付款/回款权限的管理员可下载；不会进入静态目录或商品 OSS 地址。

## 候选验证

1. 在独立数据库建立已部署 schema 基线，按顺序执行新增 migration，核对没有修改旧 Reward 余额。
2. 执行基金集成测试：`FUND_LEDGER_INTEGRATION=1 DATABASE_URL=<本机隔离fund_test库> npx jest --runInBand src/modules/fund-ledger`。测试代码拒绝非本机或非 fund_test 数据库。
3. 验证普通/VIP 计提、售后冻结/冲回、付款预留/确认/取消/冲正、回款、幂等、并发、账本余额及凭证权限。
4. 账本总览和公司子账对账一致后，按项目受控候选流程申请后续推送与环境验收。

## 回退

新账已有数据后，不能仅回滚到仍向个人分配产业基金的旧代码。先暂停新计提及付款写入，保留所有公司账、审计表、来源分配和请求标记；优先以兼容修复版本恢复。数据库金融流水不因代码回退删除，已发生银行付款按真实事实保留。

若新功能尚未启用且新公司账和付款表全部为空，可在维护窗口评估回退新模块；审计与期初表仍保留以便核查。任何移除触发器或新增表的操作需独立审查，不随 git revert 自动执行。

本说明没有执行线上迁移、生产变更或真实银行付款。
