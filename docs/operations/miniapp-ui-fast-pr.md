# 小程序展示改动快速 PR

> 2026-10-10 用户明确选择：定向 CI、一次独立审查、一次 PR，保留 main 保护。
> 本文仅补充 `branch-strategy.md` 中小程序纯展示改动的验证路径；资金、库存、支付、认证、API、Schema、依赖和发布配置继续执行原门禁。

## 适用范围

快速路径由 `scripts/ci-release-scope.mjs` 保守判定，不能仅按修改行数判断风险：

- 首页已有展示逻辑，以及 PageHeader、SeafoodImage、功能图标、头像等白名单展示组件。
- 样式仅允许首页、PageHeader、功能图标、头像四处 SCSS，以及小程序自己的 PNG/JPEG/WebP 资源；会员、余额、售后等其他区域默认完整验证。
- 可随附 `plan.md` 与小程序架构文档；文档单独修改不自动获得 UI 快线资格。
- 最多 12 个文件、展示代码补丁最多 120 行。TSX 使用锁定版本的 TypeScript 解析器，正向允许已有身份/资料字段的只读展示条件和文案/样式属性，保留非展示语法和 JSX 层级的比对；查询配置、认证条件、缓存策略、状态写入、事件、路由、API、import 等变化均回到完整门禁。关键词检查只是补充，不能代替语法判定。
- 未知路径、比较 SHA 缺失、无法计算 diff、解析器不可用、删除/重命名、symlink/submodule 或不明确的改动均退回完整门禁。后台发布调用和手动 E2E 默认强制完整验证。

白名单只是机器初筛；一次独立审查仍需确认改动确实只影响展示。涉及业务规则时必须重新走完整路径。

## 一次交付流程

1. 从最新 `origin/main` 创建干净短期 worktree，仅完成本次展示需求。
2. 对受影响页面做本地渲染检查，执行小程序类型、lint、测试与构建；一次独立只读审查，无未解决 High/Critical 后创建 PR。
3. 小程序 `client-checks` 执行客户端检查；快速 UI PR 额外生成 staging/production 构建并校验页面产物。必需的 `checks` 结果同时要求客户端检查与这份候选构建成功，失败/取消不能获得绿色门禁。审阅产物同时记录实际构建 SHA 和 PR head，不能作为正式微信上传来源。
4. 必需的 `e2e` 状态继续保留。UI 快线只执行范围判定和门禁校验，跳过未变化的后端/数据库/Web E2E；其他范围完整执行原 E2E，失败、取消或未知状态均不能获得绿色门禁。
5. staging/production 发布构建显式要求 checks 成功且 workflow 未取消，避免 PR-only 候选任务的 skipped 状态连带跳过正式构建。保留一个 PR。按用户已授权的范围合入 main；最终 main SHA 再通过小程序 CI/production build 后，按独立授权上传微信。

纯展示候选直接在自己的干净 worktree 编译/渲染，使用现有 API，不提升 `staging-next`、不重绑固定测试目录，也不重发未变化的 API/Admin/Seller。若需要后端联调、账号/支付真实流程或共用固定测试目录，则使用完整测试发布路径。

快线的 staging-next push 不触发服务器重发；固定目录同步脚本仍保持原 exact-SHA 门禁，不用于此快线。手动部署与完整 release train 的保护、备份、迁移和回退要求均不变。

## 验证证据和发布边界

- 本地渲染、客户端 CI、代码审查、微信上传、手机验收、提审、正式发布分别报告。
- 相同已测试 SHA 不重复执行无关测试；SHA 变化只重新验证受影响的端与对应范围，不把旧 SHA 的结论冒充新 SHA 的验收。
- 合并 main 的授权不扩大为服务器或微信发布；上传开发版本也不代表已提审/正式发布。
- main 的 PR、`e2e`/`checks`、strict 和管理员约束保留，无需为小 UI 改动临时取消保护。
- 回退 UI 提交后重建客户端产物；无数据变更时无需数据库回退。其他变更按原 runbook。
