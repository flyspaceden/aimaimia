# App 与小程序简单前端快速 PR

2026-10-10 用户授权：App、小程序的小范围文案、样式和简单前端交互，在一次独立审查和定向检查通过后，直接通过一个快速 PR 合入 main，保留 main 保护，不重复询问同一小改动的主线合入授权。

本文替代 `miniapp-ui-fast-pr.md` 的小程序专用快线，补充分支策略、响应式规范和审查清单中小改动的适用路径。服务器部署、App OTA/Build、小程序上传/提审/正式发布仍按明确授权分别执行。

## 范围与判定

按风险和代码语义判断，不仅看行数。自动判定来自 `scripts/ci-release-scope.mjs` 与 `scripts/ci-frontend-syntax.mjs`。

| 可进入快线 | 回完整验证 |
|---|---|
| 现有页面/展示组件的文案、图标、静态样式 | 登录/权限/隐私、资金、库存、订单/退款/奖励等敏感区域或字段 |
| 组件内部独立的展开收起、本地弹层、展示 Tab 状态 | 查询参数/缓存策略、effect、网络、存储、共享 Store/业务状态写入 |
| 静态跳转到已存在且已注册的非敏感页面 | 动态路由/参数、新路由配置、支付/认证等目标跳转 |
| App StyleSheet 的纯样式值，小程序非敏感 SCSS，本端 PNG/JPEG/WebP | 原生模块/runtime/依赖/环境/发布配置、API/Schema、业务合同类型 |

- App 覆盖 `app/` 的现有非敏感 TSX 页面和 `src/components/`；小程序覆盖 `miniapp/src/pages/`、`packages/`、`components/` 的现有非敏感 TSX，而不再只允许首页。
- 本地 UI 状态只允许组件内部、来自 React 的独立 `useState`；初始化为字面量，仅被展示或本地 UI 事件使用。进入查询、effect、业务回调或存储时自动回完整验证。
- 事件只允许本地 UI setter 或静态已注册页面跳转；已有业务事件、业务事件之间的嵌套关系、其他函数调用和 import 保留比对。未知/被 shadow 的函数不按只读处理。
- 最多 12 个文件、TSX 补丁最多 120 行；新增/删除/重命名页面或未知语法、symlink/submodule、缺少 SHA/解析器/比较失败均回完整验证。可随附 `plan.md` 和相关客户端架构/响应式文档。
- 白名单是机器初筛，独立审查仍确认业务规则/权限没有变化。发现风险就升级验证，不以“前端”或“只有几行”为豁免理由。

## 一次交付流程

1. 从最新 origin/main 创建干净短期 codex worktree，仅实现本次目标。默认同时检查 App/小程序是否适用；用户限定单端时只实现该端。
2. 做本次受影响页面的渲染/交互检查。App 按影响选择窄屏、大字体、安全区等适用场景，普通文案小改不重复跑所有页面与十种设备场景；自动化不能冒充真机验收。
3. 一次独立只读审查。修复发现后仅复核修复点，除非范围/风险变化，不重新启动整轮审查。
4. 推送一个逻辑提交、创建一个快速 PR。`Buyer Frontend CI` 根据 diff 选择受影响端：App 类型、相关 Jest 测试、Android/iOS 导出与资源/字体检查；小程序类型、受影响文件 lint、相关 Vitest 测试、目标环境构建与页面产物校验。没有相关单测时明确记录，以页面/交互检查和构建补足，不把“零测试”说成单测验收。
5. main 的 `checks` 要求每个受影响端成功；未受影响端明确 skipped。`e2e` 对 App UI/小程序 UI/跨端 UI 模式跳过未变化的后端/数据库/Web E2E，对完整模式继续执行原 E2E；失败、取消或未知状态不能得到绿色门禁。
6. 一次审查和所需 CI 通过后，直接正常合入 main，不先强制提升 staging-next、部署服务器或重绑固定测试目录，不重复询问已授权的小改动合入。main 保留 PR、checks/e2e、strict、管理员保护和禁止强推/删除。

构建与客户端检查在同一受影响端任务内完成，避免 PR-only 候选任务 skipped 传播到正式构建。App/小程序并行检查，两端代码未变时不检查该端。共享后端/法律资源和 CI 引擎变化保守检查两端；未知/手动范围检查两端客户端，并保留完整后端门禁。

## 来源、发布和回退

- PR 构建仅是候选：产物记录实际构建 SHA、PR head、目标端/环境和测试选择。正式客户端交付使用 exact-main、干净来源及 main 构建产物，不能拿 PR merge SHA 冒充正式来源。
- main push 会构建受影响端的 production 产物；测试分支构建 staging 产物。手动目标必须与 main/staging 源分支匹配，错误目标直接失败。
- App 导出只生成包，不执行 EAS update/build；小程序构建不执行微信上传/提审/发布。客户端正式生效按后续明确授权及各端 runbook 处理，记录 runtime/manifest/微信平台状态和真实设备证据。
- UI 快线的测试候选 push 不重发未变化的 API/Admin/Seller；若要真实后端联调或使用共用固定测试目录，继续执行对应部署、备份与同步规则。冻结 staging 不变。
- 相同已验证 SHA 不重复跑无关测试；SHA 改变仅重新核对受影响范围，不沿用旧 SHA 的验收冒充新版本。
- 回退小改动提交后重建对应客户端产物；没有数据写入则无需数据回退。完整业务改动仍按原运维门禁处理。
