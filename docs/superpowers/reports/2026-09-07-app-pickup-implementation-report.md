## 实现范围

普通商品、团购、VIP 礼包结算均支持配送/自提选择，复用服务器点位、中心仓授权和零运费计算。App 新增取货凭证页，订单 READY 可进入查看，短码/二维码只保留在页面内存，按前后台、账号和凭证状态撤回。VIP 增加 APP 场景的待支付发现接口，复用原会话和渠道恢复；通用 pending 检查目标 ID 与支付场景。

支付仍沿用现有支付宝/微信 SDK。微信仍只在 Android 开关允许时可用；不扩展 iOS 微信能力。不修改 schema、migration、小程序 UI、卖家/管理后台、配送业务或资金规则。新增接口部署是 App VIP 恢复上线的前置条件，旧后端未提供接口时 App 显示查询失败并停止新 VIP 创建，不静默绕过恢复防重。

浏览器 fixture 覆盖：

- 普通商品与 VIP 在没有地址时填写取货人、选择中心仓，捕获正确 PICKUP 请求及支付宝渠道；没有 addressId，普通商品应付 20 / VIP 399 与 fixture 报价一致。
- 团购自提 20 / 配送 28，分别带自提信息或 addressId；创建接口以明确 QA_STOP 响应截断，未调支付。
- 明确 INVALID 拒绝后改配送可新键重试；UNKNOWN 且 pending 暂无结果时不允许第二次创建。
- 团购初始报价 20、提交前报价 25 时首次不创建会话，显示新金额并要求再次确认；再次点击才提交 25。
- VIP pending 只调用专用接口；目标不匹配不续付另一单；小程序会话及 Web 上微信原渠道入口禁用；第一次网络失败后可重新发现原目标。
- READY 详情进入凭证、正常 PNG、图片损坏短码兜底、刷新换码、失效撤码；VIP 成功页可达实物订单。

本机复验脚本/日志/截图位于 `/tmp/app-pickup-qa/`，临时数据全部为人工 fixture；不含真实支付凭据。启动 Expo 的 CI 模式禁用热重载，最终页面验证使用 8090/8091 清缓存的新 bundle，并用独立依赖导出的 Web 产物在 8092 复验主要流程，避免将旧页面结果用于最终代码。

## 审查及修复

子 agent 分别承担支付恢复、共用选择/团购、凭证/订单入口，主 agent 逐项查看 diff、核对契约并整合。独立交叉审查发现的 High/Medium 已修复并复核：

- 无地址或未填姓名时不可把整个选择组件禁用；配送提交不依赖自提点成功。
- 企业预览剔除奖品后更新真实企业集合，上游查询失败可恢复。
- 创建/续付响应、SDK 返回、确认轮询、导航及取消回调均检查当前账号/页面有效性。
- 普通、VIP、团购的原会话恢复与未知结果保守处理；跨小程序 VIP 挡单有明确回原端提示。
- 明确业务拒绝与未知失败分开，避免更改点位后永久卡住。

限定本需求范围的最终独立复核无剩余 High/Medium；这不替代原生真机和正式环境验收。

## 版本管理与后续门禁

设计文档先作为独立本地提交保存。实现只写该 main-based worktree，没有混入原始 staging 脏目录。测试门禁为两份已审阅后端文件登记精确 blob 与 main 来源，不放宽整个后端目录；路由检查修复中文路径 URL 解码，并新增 App VIP 路由断言。

下一阶段需要真实测试环境的该候选后端、Android 两渠道和 iOS 支付宝 App，再跑设计验收矩阵。发布前按 `docs/operations/branch-strategy.md`、`github操作.md`、`app-发布与OTA手册.md` 执行。App 回退到上一包/更新；不删除自提表、点位或关闭共享自提开关，以免影响小程序。新增只读接口兼容旧客户端。
