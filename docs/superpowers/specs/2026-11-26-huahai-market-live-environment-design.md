# 华海 AI 农贸市场 · 真实养殖环境数据接入设计（第一步）

状态：已定稿。2026-11-26 起草，同日用户回答第 11 节两个问题后定稿；未实施。
前置：`docs/superpowers/specs/2026-11-24-huahai-market-trace-demo-design.md`（演示版，已上线 market.huahainongke.com）。

## 1. 目的

农贸市场网站现在全部是演示数据。本期让网页上出现**第一批真实数据**：物联网平台里真实塘口的养殖环境（水质）读数和曲线。别人打开网站，看到的是此刻塘里真实的水温、溶解氧、pH 等，而不是编的。

这是“养殖端 → 销售端”真实打通的第一步。批次、饲料、检测、商品关联、真实下单都不在本期。

## 2. 用户已确认（2026-11-26）

- 现在**只公开养殖环境**（水质等探头数据）。
- **不公开**：放苗、转塘、分塘、起捕、死亡等养殖事件；员工姓名；预警记录。
- **可以公开**：供应商名称、精确位置、存塘量（目前系统里没有这类真实记录，等有了再展示，不在本期）。
- 第一批只公开一口塘：华海公司 → 阳江永兴基地 → 测试1塘。这是目前唯一有真实数据的塘。
- 网站上真实数据和演示数据可以混着放。
- 目前物联网平台里还没有真实养殖记录（批次、投喂、化验单、照片均无）。
- 测试1塘对外显示名为“永兴 0 号塘”（系统里的名字不动）。
- 现在不要求探头做过校准核对，读数直接显示。

## 3. 现状（已核对代码和部署记录）

- 物联网平台（`华海农业物联网/`，生产代码 a90ce31）所有数据都要登录才能读，没有任何匿名或分享链接接口；每个接口路径在两层 nginx 里逐条放行。
- 物联网服务器（172.17.228.115）没有公网入口，只能从官网服务器（8.163.16.32，也叫边缘服务器）走内网进。
- 农贸市场网站是纯静态站，就放在官网服务器 `/www/wwwroot/market.huahainongke.com/`，通过 GitHub 的 `huahai-market` 发布目标整目录替换（带回退）。网页和 nginx 的安全策略都写着“禁止任何网络请求”（`connect-src 'none'`）。
- 测试1塘现有 1 个盒子、6 个探头、17 个通道；平台“塘总览”为它配置了 10 项读数（带读数标签），小程序和后台看到的就是这 10 项。
- 平台读数的读取路径：登录身份 → 设置 `farm.actor_id` / `farm.organization_id` → 通过 SECURITY DEFINER 函数读。后台任务有“系统任务身份 + 任务范围”（`farm.runtime_task_scopes`，任务名是写死的白名单，身份是整公司可读）的既有做法。
- “塘总览”读数由 Python 组装（`src/huahai_iot_farm/overview.py`）：读哪几项是**按公司**配置的，标签取自现场人员填的探头名称等文字，且不按质量、校准状态过滤。
- 曲线读取函数 `farm.iot_unit_telemetry` 每段只取最后一条样本、最多 500 段、最长 31 天，**不提供最小/平均/最大**；按真实采样密度一次读 30 天会很慢甚至超时。（写计划时核实：历史索引 `farm.history_index_series` 及其后台进程没有在线上启用，不能依赖。）
- 平台里存在测试来源（`TEST_GENERATOR`）的数据；预警等内部逻辑只信任质量为 GOOD 且校准已核对的读数。

## 4. 目标 / 不做 / 绝不能出现

**目标**
- 网页显示已公开塘口的真实最新读数和 24 小时 / 7 天 / 30 天曲线。
- 每个数字都能看出是真实还是演示，以及是什么时候采的。
- 物联网平台对公网保持关闭。
- 以后加公开塘口，不需要改代码。

**不做（本期）**
- 批次、放苗、投喂、检测报告、照片、供应商、存塘量。
- 预警记录、适宜区间、越线标记（预警不公开；塘也没有登记品种）。
- 后台里的“公开”开关页面（本期由运维按用户指定登记，见 6.1）。
- 商品与批次关联、真实下单。

**绝不能出现**
- 把演示数据标成真实，或把真实数据悄悄换成编的。
- 探头已经停了，网页还显示成“实时”。
- 导出内容里带出不该公开的东西：员工姓名、预警、养殖事件、设备序列号、内部编号。
- 公网请求能打到物联网平台的接口或数据库。
- 真实数据取不到时，把原来能看的演示页面一起弄坏。

## 5. 方案取舍

| 方案 | 做法 | 取舍 | 结论 |
|---|---|---|---|
| A 定时公开档案 | 物联网服务器每 5 分钟生成一组只含已公开塘口的数据文件；官网服务器从内网取回，放在网站自己的目录里；网页只读这些文件 | 公网永远碰不到物联网平台；物联网出故障时网页仍能显示上一份数据并标明时间；数据有约 5–10 分钟延迟 | **采用** |
| B 公开只读接口 | 物联网平台新增匿名接口，经官网服务器转发给网页 | 秒级实时；但给平台开了第一个匿名入口，要过行级权限和两层放行，出错面大 | 不采用 |
| C 人工导出 | 每次由运维导出一份数据再随网站发布 | 最省事；但不是持续更新，名不副实 | 不采用 |

用户把“怎么做”交给了设计方，以上为设计方选定。

## 6. 设计

### 6.1 物联网平台：公开登记 + 定时导出

- **公开登记表**（新表，随迁移创建）：记录哪口塘对外公开。
  - 塘一级：塘、公开代号（如 `yx-00`，用在网址和文件名里，不用内部编号）、公开显示名、是否启用、登记人、登记时间；所属基地和公司的公开代号、公开显示名（不填则用系统里的名称）。
  - 读数一级：这口塘公开哪几项读数（指向具体通道）、每项的**公开标签**、显示顺序。
  - 公开的读数和标签在**登记时定下来**，之后不跟着平台内部的“塘总览”配置变化。初始内容取测试1塘当前塘总览的那几项；公开标签由运维重新拟（如“溶解氧 · 1 号探头”），不直接用现场人员填的探头名称，避免带出人名。上线前把这份清单给用户过目。
  - 本期只登记测试1塘，由运维按用户指定写入；以后做后台开关页面时直接读写这张表。
- **导出任务**（新的 Python 后台定时任务，每 5 分钟一次）：
  - 沿用平台现有“系统任务身份 + 任务范围”的做法，新增一个任务名；不在公司人员名单里新建成员。
  - 这个身份和其他系统任务一样能读整个公司，所以“只导出登记过的塘和读数”由导出任务自身保证：只按登记表逐项取数、只输出白名单字段（见 6.3），并有测试断言未登记的塘和字段不会出现。
  - 测试来源（`TEST_GENERATOR`）的读数一律不导出。不按校准状态过滤（用户已定）；被系统明确判为坏值的读数不导出，该项按“暂无读数”处理（设计方决定，见第 10 节）。
  - 曲线用现有的 `farm.iot_unit_telemetry` 读取：按天分小段读，并在上一份导出的基础上只补新的时间段，每天整体重读一次。不依赖历史索引（线上未启用）。
- 生成的文件写到物联网服务器本地一个专用目录，先写临时文件再改名，避免读到半个文件。
- 物联网服务器内部的 nginx 把这个目录作为**仅内网可访问**的静态文件提供给官网服务器。

### 6.2 官网服务器：取回 + 对外提供

- 定时任务每 5 分钟从内网取回文件。取回后先检查：是合法 JSON、版本号认识、大小在上限内、公开代号格式正确；通过才替换旧文件。检查不过或取不到，保留旧文件。
- 文件放在 `/var/www/huahai-market-live/v1/`，**不在网站发布目录里**，这样每次网站发版不会把数据冲掉。
- 网站 nginx 新增 `/live/` 位置指向该目录：只允许 GET，只提供 `.json`，缓存 60 秒。
- 网站安全策略从“禁止任何请求”放宽到“只允许请求本站”（`connect-src 'self'`），网页里和 nginx 里两处一起改。其余策略不变。

### 6.3 数据格式（v1）

`/live/v1/index.json`
```
{ "schema": 1, "generated_at": "<时间>",
  "company": { "name": "…" },
  "bases": [ { "code": "yx", "name": "…", "province": "…", "city": "…", "district": "…",
               "address": "…", "lat": 0, "lng": 0,
               "ponds": [ { "code": "yx-00", "name": "…", "area_value": 0, "area_unit": "亩",
                            "readings": [ { "key": "r1", "label": "…", "metric_name": "溶解氧",
                                            "unit": "mg/L", "value": 0, "observed_at": "<时间>" } ] } ] } ] }
```

`/live/v1/pond-<公开代号>.json`
```
{ "schema": 1, "generated_at": "<时间>", "pond": "yx-00",
  "series": { "24h": [ { "key": "r1", "points": [[<毫秒时间>, <值>], …] } ],
              "7d":  [ 同 24h ],
              "30d": [ 同 24h ] } }
```

- 以上就是全部字段。导出里不得出现其他键；测试要按白名单逐键断言。
- 三个范围都是单条曲线（每段取该段最后一次读数，与平台后台和小程序的趋势图同一口径）。不做最小–最大范围带：现有历史函数不提供，另写汇总代价大，本期不值得。
- 每条曲线点数上限：24 小时 ≤ 300 点，7 天 ≤ 200 点，30 天 ≤ 200 点。
- `label` 是登记表里的公开标签；`name` 是公开显示名。
- 精确位置（地址、经纬度）用户已同意公开；经纬度按系统里存的原样导出（系统存的是 GPS 坐标 WGS84），网页只显示数字、不嵌地图。
- 没有数据的读数：`value` 为 `null`，保留该项，网页显示“暂无读数”。

### 6.4 网站改动

- **产地基地列表**：真实基地排在最前，带“实时数据”标识；演示基地带“演示”标识。真实基地和演示基地都列在华海农科名下，靠标识区分。
- **真实基地页**：公司、基地名称、地址与坐标、已公开塘口卡片（每张卡显示最新几项读数和更新时间）。不嵌第三方地图。
- **真实塘口页**（新路由 `#pond/<公开代号>`）：
  ```
  阳江永兴基地 › 永兴 0 号塘                    [实时数据]  更新于 14:35
  ┌溶解氧──────┐ ┌水温───────┐ ┌pH────────┐ …每项读数一格
  │ 6.8 mg/L  │ │ 24.3 ℃   │ │ 7.9      │
  │ 14:35     │ │ 14:35    │ │ 14:35    │
  └───────────┘ └──────────┘ └──────────┘
  [24小时] [7天] [30天]        ← 切换范围
  （每项读数一条曲线）
  数据来源：物联网探头自动采集，约每 5 分钟更新一次
  ```
- **首页**：现有“实时指标”区在取到真实数据时改显示永兴 0 号塘的真实读数并标“实时数据”；取不到时保持现在的演示内容。
- **顶部提示条**：从“全部为示例”改为“标有‘实时数据’的是真实监测数据，其余为演示”。
- 演示商品、演示溯源档案、B 端页面不变，继续标“演示”。
- 沿用现有浅色样式、内联 SVG 图表、无外部依赖。

### 6.5 时效与失败时的表现

| 情况 | 网页表现 |
|---|---|
| 正常 | 显示读数与采集时间；页面可见时每 60 秒重新取一次 |
| 某项读数超过 30 分钟没更新 | 该项变灰，显示“x 小时前的读数” |
| 整份数据超过 15 分钟没更新（导出或取回停了） | 页面顶部提示“实时数据暂时中断，以下为 hh:mm 的数据” |
| 数据文件取不到或格式不对 | 真实基地/塘口位置显示“实时数据暂时取不到”，首页回到演示内容；其他页面照常 |
| 塘口代号不存在 | “没有找到这口塘”，给回到基地列表的入口 |
| 某次导出拿不到曲线（如查询超时） | 保留上一份可用曲线；从未有过则显示“曲线准备中”，最新读数照常显示 |

## 7. 安全要点

- 导出任务只读、只按登记表取数；未登记的塘、未登记的读数不会被导出，有测试守住。
- 导出字段固定白名单，测试逐键断言；员工姓名、预警、养殖事件、设备序列号、内部编号一律不出。公开标签由运维拟定，不沿用现场填写的文字。
- 测试来源的数据不导出，不会被标成真实。
- 对外只是静态文件，无参数、无查询。
- 读数标签是现场人员填的文字，网页一律按纯文本转义后显示。
- 官网服务器取回后先校验再替换，坏文件不会上线。

## 8. 验证

- 物联网侧：本机测试库（`scripts/dev/live_test_db.sh`）上验证——未登记的塘读不到；登记后只出白名单字段；没数据时输出空读数而不是报错。
- 网站侧：现有模型测试和浏览器检查扩充——用本地样例 `/live/` 文件覆盖正常、读数过期、整份过期、文件缺失、文件损坏五种情况；演示页面全部照常通过。
- 上线后：核对网页读数与平台后台同一时刻同一项读数一致。

## 9. 上线涉及的地方（都需要用户届时授权）

1. 物联网服务器：一条数据库迁移（登记表 + 读取函数）、常驻导出进程、内网只读站点。物联网仓库另有会话在改，新迁移放 `sql/baseline/next/`，编号取 060（线上已到 045，锦鲤会话下一个用 046），合并时如冲突再顺延。
2. 官网服务器：取回定时任务、网站 nginx 改两处（`/live/` 位置、安全策略）。
3. 农贸市场网站：照常走 PR → main → `huahai-market` 发布。
4. 发布顺序：先 1、2（此时网页还没变化），确认数据文件正常，再发 3。

部署动作按各自仓库的规定记入部署文档。

## 10. 设计方自行决定的事项（请用户过目）

- 用“定时公开档案”而不是公开接口（第 5 节）。
- 5 分钟更新一次。
- 本期不做后台“公开”开关页面，先由运维登记；登记表为以后开关预留。
- 网址和文件用公开代号（如 `yx-00`），不暴露内部编号。
- 公开哪几项读数、叫什么标签，在登记时定下来，不跟着平台内部配置自动变；初始取测试1塘塘总览现有的那几项，标签重新拟，上线前给用户过目。
- 公司名、基地名默认用系统里的名称，可在登记表里另设公开名。
- 导出任务沿用现有系统任务身份做法，不新建公司成员。
- 三个时间范围都是单条曲线，不做最小–最大范围带。
- 测试来源的数据不导出。
- 不显示适宜区间和越线标记。
- 30 分钟 / 15 分钟两个过期界限。
- 被系统明确判为坏值的读数不显示（该项显示“暂无读数”）；其余读数不论是否校准都照常显示。实现时先核对平台里质量标记的实际取值，只挡明确的坏值，不能因为“未校准”把读数挡掉。
