## 1. 用户需求与交付目标

构建可用于爱买买、独立餐厅及第三方系统的通用视觉服务，让大部分商品随手拍获得明显、更专业的展示效果。核心服务、模型路由和图片积分不绑定某一个业务系统。

- 覆盖海鲜、农产品、包装食品、电子设备、日用品、菜品等，不能用少量关键词假设全部商品事实。
- 同时优化光照、色彩呈现、清晰度、构图、背景与商品视觉质感；不能只提供轻微滤镜。
- 合理实景应保留：床单上的手表、厨房台面的虾、餐桌上的菜品都可能是合适背景。白底由目标决定，不统一强制。
- 支持创意场景，例如番茄采摘摆盘或手捧展示；结果要有真正可使用的位置，不能付费后只剩一次性私密预览。
- 美化不能改变商品身份、型号、主要部件、包装事实、配件、固有颜色、材质或掩盖影响购买判断的瑕疵。照明色偏修正与改商品颜色应区分。
- 商家上传或编辑图片后有明确入口，可查看价格、余额、进度、对比、采用和历史；中文为主，移除不帮助决策的技术解释。
- 无逐商家 AI 白名单或人工开通流程。有足够图片积分的正常商家可以使用已开放路线；沿用所属业务的登录、商品编辑权限和租户隔离。
- 平台配置欢迎积分、方案价格与启停，查看账户、流水、费用异常并事后巡检。已上架商品换图不增加平台预审批。
- 能用免费工具时优先免费，需要模型时正常调用；优先百炼，允许可替换的其他 Provider。
- 每个逻辑改动独立审查、测试、commit。真实操作与图片质量通过后才能宣告对应能力交付。

商业目标是提高购买吸引力；是否提高转化率需后续业务对照数据，不能由图片评分直接推断。

## 3. 服务端任务作为唯一执行来源

### 3.1 执行架构

接入端 → 受管资产 → 能力/计划 → 免费任务或已确认报价 → 持久化任务 → 后台执行器 → 输出存储/检查/结算 → 候选库 → 接入端显式采用。

后台执行器负责提交、查询已绑定 Provider 任务、取回结果、检查及结算。浏览器关闭或断网不能停止服务端工作。已有定时清理租约不等于具备此执行器，需新增并验证。

数据库持久化执行状态；队列负责唤醒，不作为唯一任务存储。任务租约、重启恢复和幂等均从持久化记录判断，避免队列重复投递导致重发模型。

### 3.2 四种独立状态

| 状态轴 | 目标状态示例 | 规则 |
|---|---|---|
| 执行 | QUEUED / SUBMITTING / RUNNING / OUTPUT_STORED / FAILED / UNKNOWN | 描述模型与本地处理进度 |
| 检查 | PENDING / PASS / UNCERTAIN / FAIL | 生成成功不能代替检查通过 |
| 计费 | NOT_REQUIRED / RESERVED / SETTLED / RELEASED / RECONCILING | 检查失败不自动说明供应商免费 |
| 使用 | UNADOPTED / ADOPTED / DISMISSED / ROLLED_BACK | 关闭弹窗不改变执行或计费 |

以上是目标领域状态，不要求直接替换现有枚举。实现时映射现有模型，确需迁移则单独列出兼容、回填及回退步骤。

### 3.3 重试、恢复与报价

- 点击确认即有稳定请求标识，服务端原子绑定报价与任务。确认响应丢失后先查询同一请求/任务，不生成新任务碰运气。
- Provider 支持幂等键时使用；不支持时依靠持久化 submit 租约及请求状态。未知提交不能假定 Provider 支持去重后盲目重发。
- 同一任务只能产生一笔预期积分扣减；重复点击、刷新、后台重复投递、回调重复均不得重复扣减。
- 瞬时超时/503 保留任务记录与本地指针，显示“重新查询”。localStorage 只作缓存；按租户、账单主体和商品查询服务端历史。
- 生成中关窗仅隐藏弹窗。再打开从服务端恢复，并显示已有进度。
- 成功但不满意时可“暂不采用”并继续新方案；服务端保留候选及账务。不能强迫采用后才解锁下一次生成。
- 服务端能力和计划发生变化时刷新；最终报价过期返回结构化 QUOTE_EXPIRED。按钮改“更新报价”，清除旧勾选；新费用必须重新确认。
- 商品资料/图片变化返回 SOURCE_CHANGED 或 PLAN_STALE，保留既有任务与引用版本，重新规划后再报价；不能静默将旧任务结果绑定到新图。
- RECONCILING 显示可查询进度；后台用同一 Provider 任务恢复。仅确实需要账单证据的事项进入人工对账。
- 支持候选详情读取失败后继续取回，不能因执行状态已 SUCCEEDED 而永久停止结果恢复。

## 4. 上传、能力探测与商家界面

### 4.1 上传链路

- 客户端校验格式/大小/像素，必要时生成上传副本并保留本地原文件。
- 网络传输显示真实字节百分比；服务端处理阶段显示“正在处理图片”和已知步骤，不能用定时递增伪装精确处理百分比。
- 上传成功取得 assetId/receipt；较慢的解码、扫描、存储完成状态通过服务端任务查询。重试按资产摘要/上传请求标识去重。
- 超时区分“传输失败”和“服务器结果待确认”。后一种先查询回执，不直接要求重新选文件。
- 原图未写进商品草稿也可创建美化任务，但必须绑定所属商家、受管 assetId 和稳定商品草稿/接入对象版本。刷新后从任务资产取回原图，不能强依赖编辑页当前 fileList。
- 资产所有权、支持格式、真实解码上限和存储访问隔离保持有效。

### 4.2 一个入口和可执行方案

商品图片区域显示“美化图片”、剩余图片积分及“图片处理记录”。打开后提供免费调优、白底/背景整理、实景精修、创意场景、清晰度修复；只展示实际可执行的能力，不能先给可点击承诺、再靠失败探测是否配置。

能力响应包含路线、可用状态、中文原因、预计耗时范围、价格或获取报价方式、输出用途；不泄露 Key、内部预算 scope 或数据库配置。确定耗时范围须有实际测量依据。

界面按“选择效果 → 价格确认 → 处理中 → 对比 → 采用/暂不采用”组织。主要说明限于费用、用途、失败后的下一步。技术诊断进入管理员详情。

前端将商品表单与 ImageEnhancementPanel、CreditSummary、TaskHistory、CandidateCompare 分开；统一控制任务状态，不能用多个独立布尔值拼接互相矛盾的界面。

## 5. 五条处理路线及事实边界

| 路线 | 目标实现 | 事实与费用规则 |
|---|---|---|
| 免费调优 | 本地受限曝光、白平衡、对比度、降噪/清晰度处理；原像素坐标和构图保持 | 不扣图片积分、不调用收费 OCR；不推断“确定无文字/条码” |
| 白底/背景整理 | 主体分割 → 蒙版与边缘验证 → 原图主体合成 → 背景与接触阴影 | 主体来自原图；透明、反光、细边缘需专项验证 |
| 实景与商品精修 | 基于问题选择局部处理、受保护区域编辑或图像模型 | 保留合理实景；受限优化质感，不新增部件或掩盖缺陷 |
| 创意场景 | 模型重构摆盘、手持、桌面等展示方式 | 作为详情/营销图使用，带适当生成标识，不能冒充数量/规格证据 |
| 清晰度修复 | 根据可辨认程度选择本地放大/降噪或模型修复 | 不仅按尺寸拒绝；无法辨认的型号/部件不能靠模型补造 |

### 5.1 免费路线新合约

新增版本化 local-photometric-v2，替代免费处理必须依赖 VERIFIED_EMPTY 的旧准入条件。不是把条码 INCONCLUSIVE 改成 NONE。

- 先完成合法文件/尺寸/所有权检查；处理不裁切、不移动部件、不更换背景、不重新生成文字。
- 对文字、条码等已检测区域可降低处理强度或保留原像素；检测不确定必须如实记录。
- 增强参数有范围，原图及结果均可预览，避免过曝、色彩剪切与过度锐化。参数范围由代表性样本评测确定并版本化。
- 请求与后台执行同时使用新处理合约；旧证据和旧任务按原版本恢复，不伪造或回填 VERIFIED_EMPTY。
- 失败允许保留原图并选择其他路线，不制造永远无法完成的检查按钮。
- 免费方案执行与采用仍可追溯，但计费状态为 NOT_REQUIRED。

### 5.2 保留主体的白底与背景

不得将“整图加一句不要改变商品的提示词”标为保真合成。先选择并实测主体分割工具，再采用原图主体像素合成。背景可白色、中性色或其他明确选择的背景。

分割可能漏细节、破坏透明材质或把背景划入主体，应验证主体完整性、边缘和遮挡；低质量结果不能声称保真。允许调整选区/提供更合适原图作为恢复方法。生成阴影不能覆盖或补造商品关键结构。

主体单独调光时使用明确、受限的局部处理合约；合成与精修区分记录，不能同时承诺主体像素完全不变。

### 5.3 创意图必须有使用闭环

保留 FACT_MAIN_IMAGE、DETAIL_IMAGE、MARKETING_IMAGE、EVIDENCE_IMAGE 的用途区分。新增“用于详情/营销展示”和下载入口，不再仅支持一次性私密预览。发布位置由接入系统已有业务权限控制。

创意图可改变展示数量和摆放方式，但需与商品售价/包装数量说明分离；必须保持商品种类与可辨认特征，不能让重构的数量冒充实物交付数量。用户“番茄采摘摆盘”是明确验收用例。餐厅菜品同样不得虚构实际包含的食材。

商家采用已上架商品图片不增加平台预审批。平台事后回滚按媒体版本 CAS 执行，不覆盖更晚修改，并通知商家。尚无对应展示图位的接入端应明确能力缺失，不收费承诺可用后只留预览。

## 6. 图像理解、编辑计划与 Prompt

廉价本地诊断先执行；简单明确的操作不必先调用视觉大模型。复杂场景或需要识别关键部件时，再使用可配置的视觉分析能力，其成本计入服务成本与已告知的方案。

每次 EditPlan 至少包含：
- 原图/参考图 ID 与哈希、商品资料版本、当前图片问题。
- 目标效果、保留的真实场景、可执行路线、实际模型/工具版本。
- 主体/关键区域蒙版引用及其可信度；缺蒙版要明确，不能用 NOT_CREATED 宣称保护完成。
- 允许编辑的区域与操作、禁止改变的结构/文字/数量/固有颜色。
- 输出角色、允许使用位置、所需后置检查、预计积分与成本范围。
- 编辑计划版本、Prompt 模板版本及实际渲染提示的摘要，能够追踪每次结果。

商品描述、OCR 文本及接入方文本是数据，不能当作覆盖系统限制的指令。客户端可选效果与模板，不发送任意模型 ID、Provider URL、费用或未经约束的自由 Prompt。

Provider 将结构化计划编译成各自支持的提示、蒙版和参考图参数；不支持某种控制时必须改变能力声明，不能仅在提示里写“受保护区域”。现有 Wan/Qwen 适配层可复用，但具体蒙版、参考图、模型和价格须在接入时依据官方文档及实测重新核验。本设计不承诺某个模型天然保证保真。

## 7. 后置检查与质量判定

- 分开判断生成是否完成、画面是否改善、商品是否一致；检查报告可追溯。
- 本地检查：可解码、尺寸、空图、严重裁切、过曝、二维码/条码变化、蒙版和边缘质量。
- 生成式路线增加原图/候选结构对比：数量、主要部件相对位置、包装文字、关键颜色和材质。手表的表冠、表盘、表带关系为必测反例。
- 检查必须按 EditPlan 的授权操作及输出角色裁决：FACT_MAIN_IMAGE 保护实际数量与部件；MARKETING_IMAGE 中明确授权的展示数量、位置和摆盘变化不算事实冲突，仍核对商品种类、可辨认关键结构和套餐/交付数量声明。不能用主图数量不变规则把番茄摆盘路线全部拒绝，也不能用营销角色放行错品种或错部件。
- OCR 能辅助文字一致性，不能证明商品结构；视觉模型检查也存在误判，必须记录置信度及不确定。
- 明确结构/事实冲突 → FAIL，禁止该候选被采用；不能显示绿色“检查通过”。
- 未发现冲突但无法充分验证 → UNCERTAIN，如实说明具体未确认项。低风险路线可由商家显式核对采用并进入事后巡检；关键结构无法确认的事实主图应走保留主体路线或重新提供图片，不转为平台预审批。
- 只有对应检查实际运行且通过才写 PASS；“高优先级巡检”不能替代结构检查。
- 已知失败样本进入回归集，按具体路线/模型版本判断是否暂停该路线；不因一条路线失败把其他可用免费和保真路线一并关闭。

## 8. 图片积分、定价与平台管理

统一用户可见单位为“图片积分”。VisualCreditAccount/Ledger 独立于商品订单支付、买家消费积分、红包和分润；不可提现或用于商品抵扣。

- 默认欢迎方案可为 200 图片积分、展示服务价值 20 元；赠送数、展示面值、适用范围和启停由后台管理，不能改写历史账务。
- 商家有足够积分即可使用已开放方案。取消逐商家 AI 开通；业务编辑权限和租户隔离继续保留。测试环境不增加调用次数或共享第三方费用限制，实际执行并发仍受服务承载能力控制。
- Rate Card 是商家报价唯一来源。测试初始化仅创建缺失初始配置或通过明确管理动作修复；商家查看方案绝不能重置管理员价格、模型、名称、暂停或赠送政策。
- 价格/模型版本变化只作用于新报价；最终执行使用商家确认的有效快照。新报价或价格变化清除旧同意状态。
- 免费任务不冻结积分。付费链路按“报价→明确确认→冻结→供应商受理→结果处理→结算/释放/对账”记录。
- 供应商成本与商家积分分别记账；生成后被判失败、不采用或回退不自动等于供应商不收费。首次确认前用短文案说明结算政策，失败补偿通过独立可审计流水处理。
- 管理员需要方案、启停、欢迎政策、余额、流水、补充积分、任务、费用异常、质量和回退页面；配置可修改、修改后生效，并能验证实际作用。运维详情折叠展示。
- 配置状态、凭据就绪和执行器健康分开显示；能力探测反映真实服务状态。

### 8.1 图片积分购买闭环（未实现）

需要套餐、购买订单、收款渠道、支付回调验签、订单幂等、积分入账、状态查询及异常对账。套餐与支付金额用服务端快照；重复回调只能入账一次。支付中不得显示已充值成功。

退款、赠送积分与购买积分的可退边界需明确并由流水/批次支撑，不允许从混合余额猜测可退金额。支付渠道、套餐金额、退款条款、收款主体及法律文本列为实施前待定项，本设计不擅自决定。待定期间应提供真实可用的人工补充入口并明确在线购买未开放。

## 9. 通用 API 与跨系统接入

保留已有 `/visual-agent/v1` 资产、计划、报价、任务确认/查询、积分和 adopt-intent 接口。API Key 确定租户与客户端范围；Provider Key 只在服务端使用。

目标新增能力：capabilities、任务列表/详情、结果下载、候选放弃/归档、执行状态通知。具体路由与 DTO 在实现前补契约，不能把设计接口当成已可调用 API。

- 新系统使用统一客户端/SDK提交自己的对象编号、图片和目标，获取任务及结果，无需重写图片处理 Agent。
- 现有服务端 HMAC Evidence 合约保留并封装到 SDK；公共 API Key 不等于能随意伪造账单主体或业务版本。
- 接入端负责把已选结果存入商品/菜单对应位置。核心服务不直接写餐厅或第三方数据库。
- 第三方采用结果失败可以幂等重试采用，不重新生成或再次收取模型积分。
- 完成通知通过签名 Webhook，事件 ID 去重、有限重试、失败记录与查询补偿；回调地址需服务端登记及出站安全校验。Provider 回调与对接系统 Webhook 是两类接口，不能混称已实现。
- 撤销客户端 Key 不删除历史账务；按权限控制历史结果访问，任务执行与计费策略需显式处理。

### 10.1 必测操作矩阵

| 场景 | 验收重点 |
|---|---|
| 新上传原图尚未自动保存时美化 | 资产归属与版本绑定；刷新能恢复源图 |
| 大图、慢网、服务端处理慢 | 真实上传进度；处理步骤；超时回执查询与重复资产去重 |
| 报价等待过期 | 按钮和错误正确；新报价重新确认；无模型请求 |
| 报价后修改标题/分类/原图 | 旧计划不能错误执行，刷新后的报价绑定新版本 |
| 双击确认、响应丢失、重复回调 | 一次任务、一笔积分预占与结算；未知结果不重发 |
| 生成中关闭、刷新、换页面 | 后台继续执行；任务列表恢复 |
| 候选详情暂时读取失败 | 已成功任务仍可取回，无需再付费 |
| 生成成功但不采用 | 可继续其他图/方案；历史候选可回访 |
| 免费/付费/不同原图交叉 | 不串源图、标题、任务、价格或采用结果 |
| 第二商家首次使用、余额不足 | 无人工开通；赠送幂等；隔离有效；不足明确处理 |
| 管理员改价、暂停、补充积分 | 新报价正确、旧报价按约定处理、初始化不覆盖配置 |
| 采用与回退 | 草稿与已上架路径分别验证；原图/历史保留；CAS保护新修改；通知正确 |
| 营销图与主图 | 营销图位能使用；不能冒充规格事实；关闭后不锁死 |
| 不支持格式、低清、局部遮挡、敏感文字 | 解释准确，提供可执行替代路线，不能全部粗暴拒绝 |
| 外部接入 | Key/HMAC范围、结果使用失败重试、Webhook重复及失败恢复 |

源码字符串断言只能作辅助契约检查。需要真实组件交互/浏览器行为测试，以及实际后端和数据库的任务/积分行为验证；全站 E2E 数量不能代替图片 Agent 覆盖率。故障注入在隔离测试环境使用可控 Provider，真实模型用于验证接入和效果，避免为每个网络失败测试重复花费。

### 10.2 图片效果样本与完成标准

至少 40 张授权代表样本，覆盖农产品/海鲜、包装食品、手表手环、家电、日用品、菜品、反光、低光、密集文字、低清、多件套、真实背景和分割困难边缘。

逐图记录：输入、目标路线、工具/模型/Prompt版本、输出、实际耗时、供应商成本、积分变化、检查结果、人工目视商品一致性、画面改善及失败原因。

- 必测流程全部通过且没有未解决的阻断问题，才宣告流程验收完成。
- 清晰结构变化、型号文字变化或错商品不得漏判为 PASS；手表表冠反例必须入回归集。
- 效果不得普遍停留在无法分辨的微调；比较不同类别适用路线的可用率、美感改善和拒绝率。评测尺度在批量测试前固定，不事后选择成功样本。
- 保留实景路线不得无故白底化；白底路线不能靠重画商品获得整洁效果。
- 样本通过不能承诺所有图片零失误；真实用户后续采用率、投诉率和购买转化需持续观察。

## 11. 发布、回退与待定项

开发在 main-based 的干净候选 worktree进行；保留既有恢复点，变更不混入无关业务。每个逻辑审查后 commit；授权范围内推 feature/Draft PR，测试使用经过门禁的候选精确 SHA。staging-next 是测试指针，main 合并和生产发布另行记录。

状态/任务改造需保证旧报价和在途 Provider 任务可读可恢复，不能部署后清掉旧任务或重复提交。新执行器切换应避免新旧执行器同时拥有 submit 租约；版本关闭仍允许在途任务结果取回和对账。涉及新表/字段时单独记录迁移、回填及回退兼容，不把代码回滚等同数据库回滚。

实施前需补全的选择：分割工具和结构检查模型的官方能力、许可、部署资源、地区及实测成本；免费参数范围；清晰度修复阈值；购买积分的渠道、套餐和退款条款。候选工具尚未评测前不作效果、费用或免费运行承诺。

本设计完成仅代表改造依据已经写明。当前免费可用性、结构保真、多商家完整验收和积分购买等仍未完成。
