# 华海农科 AI 农贸市场交易门户

## 本次范围和依据

2026-10-09，用户提供《华海农科-AI农贸市场（系统）实施方案》，并确认首轮网站设计方向。第一版面向基地与 B 端采购商，以广东水产试点、供需对接和批次资料展示为主，采用四个页面：货源大厅、采购需求、品质溯源、交易工作台。

本轮交付为可独立运行的前端演示网站。域名规划为 `market.huahainongke.com`；保留现有 `huahainongke.com` 集团官网。最初开发轮未修改线上配置；随后用户于同日明确授权部署当前演示版到此子域名，独立发布准备见下文。

本设计仅覆盖本次交易门户前端，不替代实施方案全链路规划、集团官网、物联网、爱买买或餐厅平台设计。实施方案中的 MARL、区块链确权、金融保险、隐私计算等为目标能力，不作为已上线事实宣传。

## 页面及行为

| 页面 | 地址 | 内容及本地交互 |
| --- | --- | --- |
| 货源大厅 | `#market` | 三条演示货源、品类与品种/产地/规格联合筛选、清空筛选、详情和询价流程、采购/供货填写预览 |
| 采购需求 | `#demand` | 两条独立演示需求，分别呈现规格、采购量、目的地、交付安排及报价要求 |
| 品质溯源 | `#trace` | `HH-DEMO-001` 批次资料结构、检测资料核对清单、生产到交付节点、不存在批次提示 |
| 交易工作台 | `#work` | 履约中、待确认报价、已完成空态；示例报价、订单履约节点和交付清单 |

页面地址使用 hash 路由，支持刷新、前进/后退、深链接。只把页面、公开筛选词和状态放入地址；入驻、供货、采购表单不存储在 URL、浏览器存储或服务器中。表单关闭即清除，重新打开为空；填写结果使用文本节点展示，不插入用户 HTML。所有货源、报价、订单、主体均为演示，页面持续标注。

“申请入驻”“发布采购”“发布货源”只提供字段填写和预览，不发送申请或产生审核、合同、付款、库存扣减、订单或消息。询价/报价仅展示所选货源/需求与处理流程；不是实际报价发送入口。

## 视觉和交互

- 复用华海集团官网 Logo，主绿 `#15803d`，深绿文字 `#183b2a`，浅绿背景 `#f5f8f6`，白色内容区。
- 保留已确认的首页双栏介绍及货源列表；手机堆叠、隐藏辅助采购卡，核心动作保持可见。
- 原生 `dialog` 管理模态焦点、Escape 和背景交互隔离；关闭恢复触发位置，跨页聚焦标题。
- 搜索和表单支持 Enter；必填、数量、日期、长度与纯空白校验；修改内容后清除旧预览摘要。
- 不依赖聊天宿主、外部字体或第三方脚本；使用系统中文字体，尊重减少动态效果偏好。

## 工程入口

独立目录 `huahai-market-site/`，TypeScript 5.9.2 与根项目现有约定一致。无浏览器运行时依赖、无后端请求，不更改根依赖及锁文件。

```bash
cd huahai-market-site
npm ci
npm run typecheck
npm test
npm run preview
```

`npm run build` 先做严格类型检查，再输出可独立托管的 `dist/` 静态文件；预览默认 `http://127.0.0.1:4319`，仅绑定本机。端口可用 `PORT` 指定。浏览器集成检查另用 `tests/browser-check.mjs`，通过 `PLAYWRIGHT_MODULE` 指定本机现有 Playwright 模块路径；不新增生产依赖。测试截图写入忽略的 `.qa/`。

演示版本设置 `noindex,nofollow`；CSP 禁止跨站连接和表单网络提交。正式接入 API 后需要按实际接口更新策略，而不是移除安全边界。

## 安全及业务适用性

本轮不涉及数据库、并发业务写入、资金计算/结算、库存修改、真实订单状态迁移或认证。因此无需 Serializable 事务、CAS、迁移或 Prisma 校验；安全清单中的这些项不适用于纯展示。不得把本地工作台视为真实订单状态机实现。

本轮没有复用爱买买账户、积分、VIP、分润或数字资产，没有承诺交易门户与既有业务共用资金链路。将来接入时先明确主体、权限、收费、支付、退款、验收与纠纷规则，再做 API 和安全设计。

买家 App 与微信小程序本次不适用：用户明确要求的是独立 Web 网站，没有修改共享后端或两个买家客户端。
